# SDM-2 — Dialogue State Manager

## Цель

Сохранить контекст пользовательской консультации между сообщениями одной сессии и использовать уже найденные варианты без повторного независимого поиска.

## Архитектура

`DialogueStateStore` хранит только управляемый контекст сессии:

- текущую тему;
- цель разговора;
- выбранный месяц;
- активный тур;
- список ранее показанных туров;
- последний запрос.

Состояние не является новым источником знаний. Туры повторно загружаются через `StructuredTourRepository`, поэтому каталог остаётся источником истины.

## Поддерживаемые сценарии

1. После списка сентябрьских туров фраза «Помогите подобрать подходящий тур» сравнивает именно показанные варианты.
2. После карточки Кайласа вопрос «А сколько стоит?» относится к Кайласу без повторения названия.
3. После списка нескольких туров неоднозначный вопрос о цене запрашивает уточнение.
4. Сессии изолированы друг от друга.
5. `/api/sales/reset` удаляет контекст сессии.

## Ограничения

Состояние пока хранится в памяти процесса. Это соответствует локальному MVP. Для многопроцессного и серверного развёртывания будет добавлен отдельный persistence adapter без изменения контракта `DialogueStateStore`.
