# CB-1.5.1B — Session Security

Public widget sessions now use two independent values:

- `session_id` identifies the conversation;
- `session_token` proves that the browser owns it.

The token is generated by the server with `secrets.token_urlsafe(32)`. SQLite stores only its SHA-256 hash. Protected history, continuation and reset requests reject missing or incorrect tokens with a stable `403 session_access_denied` response.

The widget stores the token under `ai-bodhi-session-token` and sends it transparently. Token rotation is available through `POST /api/sales/session/rotate-token`.

Legacy dialogs created before this migration have a null token hash and remain readable during transition. Their first non-empty chat request claims and protects the active dialog.
