# CB-1.1.0 — Conversation Handoff Engine

## Цель

Добавить единый детерминированный механизм, который распознаёт запросы, требующие участия менеджера, запускает обязательный сбор контактов и сохраняет структурированную заявку через `LeadRepository`.

## Архитектура

`HandoffEngine` отвечает только за классификацию намерения. Он не формирует UI-текст и не обращается к базе данных.

`SalesAssistant` координирует сценарий:

1. определяет причину передачи;
2. собирает имя;
3. предлагает Telegram или MAX;
4. получает контакт;
5. получает email;
6. валидирует полный контракт;
7. формирует детерминированную сводку;
8. сохраняет заявку через `LeadRepository.save_handoff`.

## Поддерживаемые причины

- бронирование;
- уточнение наличия;
- индивидуальные условия;
- вопросы по оплате и рассрочке;
- явная просьба связать с менеджером.

Информационные вопросы о программе, цене или датах сами по себе не запускают передачу менеджеру.

## Совместимость

Старый сценарий `LEAD_NAME → LEAD_CONTACT_METHOD → LEAD_CONTACT_VALUE` сохранён. Новый handoff-сценарий использует отдельные стадии и не меняет существующие email- и artisan-сценарии.
